# Backend API

API-01 подготавливает контракты и базовый runtime сервиса поддержки: API, одноразовый мигратор, PostgreSQL, RabbitMQ, Redis и внешний Nginx. Авторизация, операции с тикетами, outbox и обработчики событий реализуются в следующих карточках; их интерфейсы уже зафиксированы в `contracts/`.

## Локальный запуск

Требуются Docker с Compose v2, `curl` и свободный локальный порт (по умолчанию 8080).

1. В корне репозитория скопируйте шаблон: `cp .env.example .env`.
2. Замените все значения `change-me` случайными локальными секретами. Используйте hex-значения из `openssl rand -hex 24` для паролей и `openssl rand -hex 32` для `SECRET`: Compose передаёт пароли в URI, поэтому неэкранированные URI-разделители не поддерживаются. Не добавляйте `.env` в Git.
3. Запустите стенд: `docker compose up --build -d`.
4. Проверьте процесс и готовность БД:

   ```sh
   curl --fail http://127.0.0.1:8080/health
   curl --fail http://127.0.0.1:8080/ready
   ```

   Если изменён `PUBLIC_PORT`, используйте его вместо 8080.

5. Для обычной остановки без удаления данных выполните `docker compose down`. Команда `docker compose down -v` удаляет локальные тома PostgreSQL, RabbitMQ, Redis и файлов и применяется только при осознанном сбросе стенда.

API слушает порт 8080 только во внутренней сети Compose. Снаружи доступны только `/health`, `/ready`, `/api/` и зарезервированный `/ws`; внутренние маршруты закрываются Nginx по умолчанию.

Перед изменением схемы или путей томов остановите запись и сделайте резервные копии. Для PostgreSQL используйте `pg_dump`, для RabbitMQ экспортируйте definitions и проверьте durable-очереди, для Redis сохраните AOF/RDB и скопируйте соответствующие именованные тома. Не переключайте путь существующего PostgreSQL-тома до проверки реального расположения старых данных и восстановления резервной копии на тестовом стенде.

## Контракты

OpenAPI-контракты и JSON-примеры RabbitMQ находятся в `backend/contracts/`. Команда `go test ./contracts -count=1` проверяет OpenAPI, все типы событий и отрицательные варианты схем.

## Проверки

Из каталога `backend`:

```sh
go vet ./...
go build ./...
go test ./... -v -race -coverprofile=coverage.out
go tool cover -func=coverage.out | tail -n 1
```

Интеграционные проверки с реальной PostgreSQL запускаются отдельно:

```sh
TEST_DSN='postgres://user:password@127.0.0.1:5432/database?sslmode=disable' \
  go test -count=1 -race -tags=integration ./...
```

`TEST_DSN` должен указывать на отдельную реальную PostgreSQL под тестовой ролью с правами создания/удаления схем и ролей. Интеграционные тесты создают и удаляют собственные схемы, а проверка readiness дополнительно создаёт и удаляет изолированную SELECT-only роль; при отсутствии `TEST_DSN` тесты намеренно завершаются ошибкой. Общая цель покрытия остаётся 80%, а для критической бизнес-логики auth/tickets следующие карточки вводят отдельный порог 95%.

Полный Compose smoke-тест запускается из корня:

```sh
bash backend/tests/compose_smoke.sh
```

Скрипт использует уникальный Compose project, временные секреты и свободный порт, проверяет миграции, публичную границу proxy, сохранность PostgreSQL/RabbitMQ/Redis, отказ БД, восстановление readiness и graceful shutdown. После завершения его временные контейнеры и тома удаляются.
